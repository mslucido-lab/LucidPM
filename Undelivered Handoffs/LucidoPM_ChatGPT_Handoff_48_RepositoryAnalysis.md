## Key Finding

This git repo contains only the Reflex **app package**, not a full Reflex project scaffold. There is no `rxconfig.py`, `requirements.txt`, `pyproject.toml`, `.env`, `assets/`, or `.web/` anywhere in the repo or its git history (checked `git log --diff-filter=A` back to the baseline commit `18cb2f3`). The code imports itself as `from LucidPM_Reflex.pages...`, and the reference template file (`LucidPM_Reflex_Install.py`) does `from rxconfig import config` — but the actual project root containing `rxconfig.py` isn't part of this repo.

This matches the old `Claude.txt` directory listing at the repo root, which shows this folder used to live nested one level inside a parent `LucidPM_Reflex` project folder (`C:\Dell Inspirion\TenantCRM\LucidPM_Reflex\LucidPM_Reflex\`). **The outer scaffold either needs to be recreated or the one on Mark's actual dev machine needs to be located** — it is not present in `C:\Inspirion\Dev\TenantCRM\` on the machine this analysis was run on.

## Language & Framework

- **Python**, using **Reflex** (`import reflex as rx`) — full-stack framework that compiles to a React/Next.js frontend + FastAPI backend.
- Backend is extended directly with **FastAPI** (`api = FastAPI()` in `LucidPM_Reflex.py`, custom routes like `/api/pick-files`), mounted onto the Reflex app.
- No Python version is pinned anywhere in the repo (no `pyproject.toml`, no `.python-version`). Reflex generally needs 3.10+.

## Build/Run System

- Standard Reflex CLI workflow (`reflex init` / `reflex run`), which also requires **Node.js** under the hood (Reflex compiles a Next.js frontend). No Node version or `package.json` is present in this repo — that's generated by Reflex itself, not hand-authored.
- **Missing**: `rxconfig.py` (app name/config) — without it, `reflex run` cannot start from this checkout as-is.

## Database

- **SQL Server Express**, local instance named `localhost\SQLEXPRESS` (hardcoded in `state.py`).
- Two databases by name: `TenantCRM` (production) and `TenantCRM_Test` (test) — toggled at runtime via `AppState.use_test_db`.
- Connects via **ODBC Driver 18 for SQL Server**, Windows trusted connection (`Trusted_Connection=yes`), encrypted, trusting the server cert. This ODBC driver is a **system-level install requirement**, not a pip package — must be installed separately (Microsoft ODBC Driver 18 for SQL Server).
- Confirmed on the analysis machine: `MSSQL$SQLEXPRESS` service is present and running.
- Schema isn't in the repo (no `.sql`/migrations folder found) — DB schema currently exists only in the live SQL Server instance(s).

## Environment Variables

- **None found.** No `.env`/`.env.example` file, and no `os.getenv`/`os.environ` reads for credentials in the live app files. All secrets (SMTP credentials, Anthropic API key, encryption key) are stored **encrypted in DB tables** (`EmailConfig`, `AppSettings`) via the `Fernet`-based `encrypt_value`/`decrypt_value` helpers in `state.py`, not via environment variables.
- `.gitignore` reserves `.env` / `.env.*` (with a `.env.example` exception) for future use, but none currently exists.
